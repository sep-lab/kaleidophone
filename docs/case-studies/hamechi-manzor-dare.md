# Case study: HAMECHI MANZOR DARE

**HAMECHI MANZOR DARE** (همه‌چی منظور داره, "everything means something") ·
Sep The Concept · September 2026 · 3:28 track, two 60 s vertical cuts · live
audio-reactive canvas, no source footage

The ninth release in the series and the first that isn't a python/ffmpeg
frame engine at all. It is a browser **canvas** piece: one self-contained
HTML file that is live art (drop the WAV on it and it reacts forever), a
deterministic offline renderer for on-beat vertical cuts, and a cover
generator. The same draw code serves all three. Its source is in this
repository at `canvas/pieces/hamechi-manzor-dare/`, and it is one of the
four canvas pieces that close
[#42](https://github.com/sep-lab/kaleidophone/issues/42) ("a fully
procedural video with no source footage").

What it proves for the framework: a completely different medium still
re-derived the same answers: an envelope-driven picture, beat-snapped cut
starts, a planned per-phrase schedule, a silent render, and the audio muxed
where the WAV lives. The pattern it set, write the draw code once and change
only the driver, is the one the next three canvas pieces used.

**What's scrubbed and why:** no lyrics. The swarm's single Persian words are
part of the piece's own design and live in its source; they are not the
song's words. The release copy isn't reproduced. The real envelope pack is
derived from unreleased audio, so the repository ships a synthetic twin
(`synthetic.json`, generated by `canvas/tools/synth.mjs`). Numbers are
**measured on the release** unless marked otherwise. The audio is private,
so they can't be re-run here.

## The rule: paranoia as meaning

One figure screams at the center. A swarm of eyes, whispering mouths and
pointed words orbits it and closes in as the track builds. The head is on
fire: pressure with no exit. Masks slam on during calm phrases, crack on
bass hits, and tear off on the loudest one. There is no on-screen data of
any kind: label nothing, react to everything.

Each part is a rule in code
(`canvas/pieces/hamechi-manzor-dare/src/00_piece.js`):

- **The walls close in.** The swarm's ring radius is a function of
  intensity: `ringScale() = max(0.60, 1.30 − 0.52 × intensity − ratchet)`.
  In the live mode a click scatters the swarm (`scatter()`), and it comes
  back 0.018 closer each time, up to 0.22. That ratchet never releases
  ([#24](../TECHNIQUES.md#24-pressure-ring-swarm)).
- **Masks are a state machine**: off → on → falling. Six masks (smile, grin,
  blank, weep, rage, polite) come from a shuffled bag. While a mask is on,
  each beat with the bass above 0.8 has a 45 % chance to add a branching
  crack with a brief ember glow (`addCrack()`). Intensity above 0.86 tears
  the mask off (`dropMask()`)
  ([#25](../TECHNIQUES.md#25-mask-state-machine)).
- **The fire is sprites.** One or two baked radial-gradient sprites are
  drawn many times with `lighter` blending over a base glow, with the spawn
  rate driven by the highs and the scream
  ([#23](../TECHNIQUES.md#23-sprite-fire)). Stroked paths read as dotted
  twigs; sprites read as flame.

Around that sit a half-resolution feedback/glow layer composited with
`screen`, film grain, scanlines and a VHS slip.

## The track

| | |
|---|---|
| Length | 208.5 s, 48 kHz / 24-bit stereo |
| Tempo | ~73.17 BPM |
| Loudest 60 s | starts ~44 s |
| Envelope pack | 100 Hz bass / mid / high / rms / flux, plus beats and drops, computed with numpy where the WAV lives |
| Beats the harness uses | the pack's own beat list. It locked onto the half-time pulse, so an 8-beat mask phrase lasts ~13 s. Without a beat list, `beatsOf()` in the driver falls back to flux peaks (mean + 1.6 sd over the last 0.72 s, above 0.10, 0.28 s refractory) |

The section levels the repository keeps are in `synthetic.json`: boundaries
at 0, 20, 44, 104, 130, 160 and 190 s, a sparse opening with no kick, and
the loudest stretch from 44 s.

## How it was built

### One file, three modes

This is the pattern the later canvas pieces copied
([#19](../TECHNIQUES.md#19-three-mode-piece)). The URL query picks the mode,
and the draw code is shared:

- **live** (no query): click, and a scheduled procedural drone plays
  (`startDrone()`: a sub-kick at the track's tempo, whisper bursts, detuned
  saws), so the live piece is never silent
  ([#20](../TECHNIQUES.md#20-live-web-audio-fallback)). Drop the WAV
  instead, and an AnalyserNode feeds the same band extraction plus a
  flux-based beat detector. It is endless. Pointer movement heats the swarm,
  a click scatters it, and Space pauses.
- **render** (`?render=1&w=&h=&seed=`): `window.__ready` is a promise that
  resolves when the fonts have loaded. `window.__frame(p)` then advances the
  simulation by one step:
  `p = {dt, beat, bass, mid, high, rms, noAutoMask, forceMaskOn, forceMaskOff, titleCard, endCard}`.
- **cover** (`?cover=1&size=3000`): `window.__cover('scream' | 'mask')`
  settles the simulation for 130 steps and sets the mask state. It then
  draws 22 frames so the glow layer breathes, and leaves a still.

`canvas/tools/build.mjs` assembles `template.html` and the module into
`canvas/dist/hamechi-manzor-dare.html`, with three Vazirmatn weights
base64-inlined from the npm package. Isolated Persian words and the title
shape correctly with the real font and `direction: rtl`, with no reshaper
([#26](../TECHNIQUES.md#26-canvas-rtl)).

**`LWF()`** ([#22](../TECHNIQUES.md#22-stroke-scaling)). Every `lineWidth`
and every word's font size is multiplied by `max(0.8, S/200)`, where S is
the head's half-height. The piece was tuned at 1080 wide and went hairline
on a 3000 px cover without it. It was the single biggest cover-quality fix.

### The one stateful piece: the harness decides

Everything carries over from frame to frame: swarm positions, fire
particles, feedback trails, the mask state. It all draws from a seeded RNG
(`mulberry32`, seed 7 for renders). So
`canvas/pieces/hamechi-manzor-dare/driver.mjs` has to do more than any other
driver ([#21](../TECHNIQUES.md#21-deterministic-render-harness)):

- **One worker, in order, with a warm-up.** A window renders in one worker,
  in order, starting 3 s early (`WARMUP = 3.0`). Those frames are drawn but
  not written, so the trails and the fire are alive on frame 0.
- **The harness decides the masks, not the piece.** `plan()` splits the
  window's beats into 8-beat phrases and masks the quieter half (at least
  three phrases). It forces the mask off on the other phrase starts and on
  the single biggest flux hit. The piece's own phrase flip is switched off
  (`noAutoMask`), so a render is repeatable.
- **The cut start snaps to a beat, and the tool says so.**
  `canvas/tools/render.mjs` prints the snapped value, because the audio's
  `-ss` must use it. On the synthetic twin it prints
  `t0 snapped to the nearest beat: 44 -> 43.885  (use THIS value for the audio -ss)`.
- **The cards.** In `reel` mode the title card holds for 1.6 s and fades out
  by 2.4 s, and the end card ramps in over the last 1.4 s. `story` mode has
  only the end card.

### The render path

Playwright drives a headless Chromium. Each frame is read with
`canvas.toDataURL('image/jpeg', 0.92)` and piped as MJPEG into
ffmpeg/libx264 (`ffmpegSink()` in `canvas/tools/lib/common.mjs`). **Measured
at 1080×1920:** JPEG capture ran at ~9.5 fps against ~4 fps for PNG, so PNG
is kept for stills and covers ([#27](../TECHNIQUES.md#27-jpeg-capture)). The
render settings in `piece.json` are 30 fps, CRF 18, `-tune film`.

## Delivery

| Cut | Window | Notes |
|---|---|---|
| reel, 60 s | the loudest minute, snapped to a detected beat (≈43.5 s) | title card (it doubles as the reel cover), then an end card. 18 MB |
| story, 60 s | from 92 s, a tenser stretch | end card. 21 MB |
| covers, 3000² | — | `scream` and `mask`, JPG + PNG |
| the live piece | — | the HTML file itself: open it and drop the WAV on it |

The silent video was rendered on a cloud machine and re-encoded at CRF 27 so
it would travel light. The WAV (~60 MB) never moved. The mux ran on the
machine that holds it, starting at the snapped `t0`:

```bash
ffmpeg -ss <snapped t0> -t 60 -i song.wav -i reel_silent.mp4 -c:v copy \
  -af loudnorm=I=-14:TP=-1.0 -c:a aac -b:a 256k -movflags +faststart reel.mp4
```

## What went wrong

- **Hairline covers.** Every stroke was tuned in 1080-wide units. At 3000 px
  it went hairline until `LWF()`.
- **Dotted-twig fire.** Stroked flame paths read as twigs. Sprites fixed it.
- **No delivered-file loudness was recorded.** The mux relied on a
  single-pass `loudnorm` with `TP=-1.0`. The later releases measure true
  peak on the delivered AAC itself, because the encoder can overshoot what
  the WAV promised ([#18](../TECHNIQUES.md#18-aac-true-peak-guard),
  [#50](../TECHNIQUES.md#50-aac-guard-per-master)).
- **The render harness wasn't kept with the release.** This matters more
  than it sounds; see the next section.

## The port in this repository

**Measured on the port:** the repository build of
`canvas/pieces/hamechi-manzor-dare/` is text-identical to the shipped HTML
apart from comments.

The repository cannot reproduce the delivered reel frame for frame. The
piece is stateful and seeded, so its output depends on the exact sequence of
`__frame` calls it receives: which step sizes, which beats, which forced
mask events, from which warm-up. The one-off harness that rendered the
release wasn't kept. `driver.mjs` is the generalized harness written after
the release. **Measured against frames decoded from the delivered reel:**
28.3 dB PSNR at frame 60, with the same mask on. By frame 450 the mask
schedule differs, and the frames diverge. The piece in this repository is
the real piece; the reel it renders is a sibling of the delivered one, not a
copy.

The lesson: **for a stateful piece, the harness is part of the source.**
Keep it with the release, or prefer a pure function of time when the concept
allows ([#30](../TECHNIQUES.md#30-pure-function-of-time)). The three later
pieces are pure functions of time, and all three reproduce their delivered
films far more closely.

**Its frames also depend on the machine's fonts.** The title and the swarm's
words are drawn in Vazirmatn, which the build inlines. The credit line under
the title, on the cards and on the covers asks for the system font instead
(`ui-monospace,Menlo,monospace` in `drawTitle()` and `drawCards()`). So a
render repeats exactly on one machine but not across machines. **Measured**
(Chromium 141, 1080×1920, t = 60 s on the synthetic twin): two renders were
pixel-identical. Switching the system monospace font from DejaVu Sans Mono to
Liberation Mono changed 454 pixels, all of them in the credit line (y 1874–1882).
The piece is frozen, so it keeps the system font. A new piece inlines every
font it draws with (`fonts` in `piece.json`).
