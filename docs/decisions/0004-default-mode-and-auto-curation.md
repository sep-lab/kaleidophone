# ADR-0004: A default mode backed by heuristic curation, not a wizard

- **Status:** Accepted
- **Date:** 2026-08-06

## Context

A brief with hand-written stations, section timestamps, and per-section
effects is real creative control, and real friction: nobody should have to
answer a wall of setup questions just to see whether this tool is worth
their time. At the same time, this project's whole reason to exist is
letting the diverse, specific creative jobs in
`docs/case-studies/love.md` be *possible* — a wizard that only offers three
canned "styles" would foreclose exactly that.

## Decision

**`kaleidophone auto <song> <photos_dir>` produces a complete result with zero
authored config, by generating a normal, fully-editable `CreativeBrief` and
running the same pipeline a hand-written brief would.** Nothing about the
brief format itself is simplified for this path — `generated_brief.yaml` is
written to the output directory specifically so "customize from here" is a
text edit and a re-run (`kaleidophone run`), not a different tool.

Auto-mode's choices:

- **Section boundaries** come from `audio/analysis.py`'s existing quiet-
  passage and energy-jump detectors — the same signals a hand-authored
  brief would mark as "the hush" / "the switch" — falling back to even
  slicing (3-6 sections) when a track doesn't hand back a usable number of
  them.
- **Station assignment** cycles a small built-in preset palette
  (`assets/stations.py`) across sections, then curates the supplied photo
  folder against *only the stations that end up used* via
  `assets/curation.py`'s heuristic scorer.

That last clause is a correction, not the original design. The first
implementation scored every "warm" station (amber-room, gold-hour,
fire-leak — three of the four presets) against the same fixed target hue,
so they competed for identical-looking photos; run against this project's
own synthetic demo fixtures, it handed `amber-room` **zero** photos and
crashed `compose()` outright. Two fixes, kept together on purpose: the
scorer now derives each station's target hue from its own duotone color
(so presets actually differ), and `build_default_brief()` never hands
`compose()` a section pointing at a station curation left empty — it
assigns sections only after curation, cycling exclusively through stations
that received something. Belt and suspenders: better scoring reduces how
often a station comes back empty; the ordering fix guarantees the pipeline
can't crash even when one does.

## Consequences

**Good**

- `kaleidophone auto song.mp3 photos/` is a complete answer to "does this tool do
  anything useful," with no brief-authoring tutorial required first.
- The auto-generated brief is a real worked example of the schema, seeded
  with a specific song's real analysis — often a better starting template
  to edit from than a blank one.
- The empty-station guard is defensive at the right layer: `compose()`
  still fails loudly on a *hand-authored* brief that genuinely
  misconfigures a station (that's a real bug worth surfacing, per
  `AGENTS.md`), while auto-mode simply never produces that situation.

**Bad, and accepted**

- Auto-mode's section boundaries and station-cycling are simple heuristics,
  not a claim of good taste. `docs/case-studies/love.md`'s actual structure
  (four hand-curated stations, a hand-placed "switch" at 3:28.3, an
  8-block-long strobe-archive section) was authored by a person, not
  generated by this code path — treat `kaleidophone auto`'s output as a first
  draft to look at via `kaleidophone preview`, not a finished edit.
- Photo curation is still the same cheap heuristic ADR-0002 chose over a
  vision-model call, so auto-mode's station split can be visibly wrong on
  an unusual photo set. It's a sort order to skim, not a decision to trust
  blindly — same caveat as `kaleidophone curate` standalone.

## What would overturn this

- If real usage shows people mostly throw away the generated brief and
  start from scratch, the "editable starting point" value proposition is
  wrong and auto-mode should optimize purely for output quality instead of
  legibility of its choices.
- A vision-model-assisted curation pass (see ROADMAP.md) that meaningfully
  beats the heuristic scorer on real, messy photo libraries would be grounds
  to make it the auto-mode default, with the deterministic scorer kept as
  the no-API-key fallback.

## Update, 2026-08-06

Writing `tests/test_stations.py` turned up a narrower recurrence of the same
mechanism: `fire-leak`, the fourth warm-temperature preset, still had
`duotone=None`, so it fell back to `_target_hue()`'s coarse guess and landed
within a few hue units of `amber-room`'s and `gold-hour`'s real
duotone-derived hues -- the first fix (deriving hue from duotone) only helps
a preset that actually sets one. Gave `fire-leak` its own duotone; see
CHANGELOG.md. Left as a reminder that this class of bug is per-preset, not
fixed once for the whole palette -- `tests/test_stations.py` now asserts
every shipped preset has a duotone specifically to catch a fifth.
